# itzephir-pub

Посты для [@itzephir_pub](https://t.me/itzephir_pub) в Markdown: превью через PR, публикация из `main`.
Тестовый канал — `itzephir_pub_nightly`.

**Telegram пока выключен.** Репозиторий работает без Telegram-токенов и сессий:
Actions проверяет посты, собирает превью и сохраняет артефакты. Доставка включается
отдельно для превью и релизов после настройки доступа.

## Написать пост

Скопируй `templates/post.md` в `posts/` и напиши свой текст:

```markdown
---
id: my-first-post
status: draft
---

# Заголовок

Текст с **выделением**, [ссылкой](https://example.com) и `кодом`.
```

- Один `.md` файл — одно обычное текстовое сообщение Telegram, до 4096 символов после преобразования разметки.
- `id` — постоянный уникальный идентификатор. Его нужно сохранить при переименовании или перемещении файла.
- `draft` позволяет увидеть пост в превью PR и исключает его из релизного канала.
- Чтобы выпустить пост, поменяй статус на `published` и влей PR в `main`.
- Изменение опубликованного поста обновляет то же сообщение с сохранением ссылки.
- Возврат к `draft` и удаление файла не удаляют уже опубликованное сообщение.

В репозитории есть один **черновик-пример**, который не попадёт в основной канал.
Авторский процесс подробнее описан в [docs/writing-posts.md](docs/writing-posts.md).

## Что делает Actions

| Событие | Сейчас | После подключения Telegram |
| --- | --- | --- |
| Открытие/обновление PR в `main` | Проверка всех постов, превью изменённых постов в Summary и артефакте | Новые или обновлённые сообщения в nightly |
| Push в `main` | Проверка и релизный артефакт для `published` | Новые публикации и правки существующих сообщений |
| Ручной запуск Preview/Release | Сборка соответствующего артефакта | Release также сверяет текущее состояние `main` с Telegram |

Артефакт содержит `preview.md`, текст и Telegram HTML каждого поста, а также
`manifest.json` с ID, статусами и хешами. Он позволяет проверить преобразованный
контент, но окончательный внешний вид сообщения нужно будет проверить в Telegram.

Реальная доставка управляется **repository variables**:

```text
TELEGRAM_PREVIEW_ENABLED=true
TELEGRAM_RELEASE_ENABLED=true
```

Если переменные отсутствуют или отличаются от `true`, отправляющие jobs пропускаются.
Эти переключатели независимы: сначала можно включить только nightly.
Инструкция на будущее: [docs/telegram-setup.md](docs/telegram-setup.md).

## Локальная проверка

Нужен Python 3.12 и Git:

```sh
make install
make check
make preview
make release-plan
```

Результаты находятся в `build/preview/` и `build/release/`. Эти команды не входят
в Telegram и ничего туда не отправляют. `publish` тоже работает как dry run, если
не передать `--live`; одного `--live` недостаточно без включённой переменной.

```sh
.venv/bin/python -m postpub publish --target release --output build/dry-run
```

## Авторство и состояние

Отправитель использует **личный аккаунт**, проверяет его числовой ID и явно
выбирает его через `send_as`. Бот-сессии и подмена личного автора именем канала
отклоняются. Подписи и показ профилей авторов нужно настроить в каналах перед
включением доставки; CI не меняет эти настройки автоматически.

Соответствия `post ID → message ID` сохраняются в служебной ветке `telegram-state`.
Она появляется только при первом включённом запуске, которому есть что отправить.
Каждое превью имеет собственное пространство `pr-<number>`, релизы — `release`.
Повторный запуск пропускает неизменённый контент.

Перед отправкой сохраняется запись `pending`. Если выполнение прервалось после
запроса к Telegram, следующий запуск останавливается для проверки результата.
Это предотвращает слепую повторную отправку; восстановления требуют действий
из [docs/recovery.md](docs/recovery.md).

Все jobs доставки используют одну очередь. Отложенный релиз сверяет **всё текущее
`main`**, а не только diff последнего push. Превью проверяет, что PR всё ещё открыт
и его head соответствует прошедшему проверку коммиту.

Превью в Telegram для PR из форков выключены; проверки и артефакты для них доступны.
Доверенный workflow берёт код издателя из `main`, читает Markdown PR из Git как
данные и не исполняет PR-код с Telegram-секретами.
